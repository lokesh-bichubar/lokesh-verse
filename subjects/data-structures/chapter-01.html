CHAPTER 01 • DATA STRUCTURES

INTRODUCTION TO DATA STRUCTURES

QUANTUM UNIVERSITY B.TECH CSE SEMESTER 01
FULL NOTES IMPORTANT QUESTIONS

1.1 What is a Data Structure?

Before we write a single line of code, we need to answer one question: how do we organize data so that our program can use it efficiently? That question is the entire subject in one sentence.

DEFINITION

A data structure is a systematic way of organizing, storing and managing data in a computer so that it can be accessed and modified efficiently — by both the program and the programmer.

Think of it like this: the same books arranged in different ways give you completely different experiences. Sorted alphabetically? Finding a title is instant. Piled randomly? Good luck. The data is identical — the structure is what changes the cost of every operation.

EXAMPLE

Problem

You have the marks of 60 students. You need (a) the average, (b) the topper, and (c) "did anyone score exactly 77?"

Solution

All three questions need the same data, but different structures make each question cheap or expensive: a simple array handles the average in one pass; finding the topper is another pass; and "who scored 77" is a search — fast if the array is sorted, slow if it isn't. Choosing the structure is choosing which operations you're optimizing for.

1.2 Why Data Structures Matter

A classic formula you'll see in every textbook:

FORMULA
Program = Data Structure + Algorithm
data (organized) + steps (to process it) = a working program

The algorithm is the recipe; the data structure is how the ingredients are arranged on the counter. A great recipe with a chaotic kitchen still produces slow food.

IMPORTANT

For the exact same task, a better data structure can turn millions of operations into a handful. Searching 1 billion sorted records takes ~30 steps with binary search, but ~1,000,000,000 steps with a linear scan. Same data. Same problem. Wildly different cost.

1.3 Classification of Data Structures

Data structures are classified along two main axes:

  • Primitive vs Non-primitive — built-in language types vs structures we build out of them.
  • Linear vs Non-linear — elements in a sequence vs elements in a hierarchy/network.

One more distinction worth knowing for theory questions:

  • Static — size fixed at compile time (array).
  • Dynamic — size grows/shrinks at runtime (linked list, and basically everything we build after Chapter 3).

1.4 Abstract Data Type (ADT)

DEFINITION

An Abstract Data Type (ADT) is a mathematical model of a data structure that specifies what operations can be performed, without specifying how they are implemented.

The ADT is the contract; the implementation is the delivery. A Stack as an ADT promises push, pop and peek — you can honour that contract with an array or with a linked list, and the user of the stack shouldn't care.

REMEMBER

ADT = the "what". Data structure = the "how". In exams this is a favourite 2-mark distinction: an ADT hides implementation details behind an interface — that's literally the abstraction in the name.

1.6 Algorithms and Time Complexity

DEFINITION

An algorithm is a finite, step-by-step sequence of unambiguous instructions to solve a problem. Time complexity measures how the running time grows as the input size n grows.

Because actual seconds depend on the machine, we count growth instead. Big-O notation gives the upper bound — the worst-case growth rate — while ignoring constants and lower-order terms.

FORMULA
3n² + 50n + 900  →  O(n²)
drop constants and lower-order terms — at large n, n² eats everything else

Rules for computing Big-O

  • Drop constants: O(5n) → O(n).
  • Drop lower-order terms: O(n² + n) → O(n²).
  • Sequential blocks add — keep the biggest.
  • Nested loops multiply: a loop inside a loop over the same data is n × n.

1.7 Best, Worst and Average Cases

Complexity isn't one number — it depends on the input and your luck:

  • Best case (Ω) — the luckiest input. Linear search finds the key at index 0: Ω(1).
  • Worst case (O) — the input from hell. Linear search finds the key at the last index (or not at all): O(n).
  • Average case (Θ) — expected over all inputs: Θ(n/2) = Θ(n).
REMEMBER

When someone says "the time complexity of X" with no qualifier, they mean the worst case. Big-O = upper bound = the promise you can't do worse than. Exams love asking for all three for linear/binary search.

1.8 Space Complexity

Time isn't the only budget — memory counts too. Space complexity is the total memory an algorithm needs as a function of input size, including:

  • Fixed part — code, simple variables, constants.
  • Variable part — dynamic allocations, recursion stack, auxiliary arrays.

Example: binary search uses O(1) extra space (a few variables), while merge sort needs O(n) extra space for merging. Recursive versions of algorithms add O(depth) stack space — that's why recursive Fibonacci is both slow and memory-hungry.
