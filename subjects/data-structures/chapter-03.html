LINKED LISTS

QUANTUM UNIVERSITY B.TECH CSE SEMESTER 01
FULL NOTES IMPORTANT QUESTIONS

3.1 What is a Linked List?

Arrays are a row of lockers: one block, fixed size, and rearranging anything means dragging lockers around. A linked list is a treasure hunt: each item knows where the next item lives, and the items can be scattered anywhere in memory.

DEFINITION

A linked list is a dynamic linear data structure in which elements (nodes) are stored at arbitrary memory locations and connected by pointers. Each node contains two parts: data + a pointer to the next node.

REMEMBER

If you lose the head pointer, you lose the entire list. There is no index, no formula, no way back — the only entry point is head. Guard it with your life.

3.2 The Node Structure

In C, a node is a struct that contains the data and a pointer to another node of the same type — a self-referential structure:

Because nodes come from malloc (the heap) one at a time, the list can grow and shrink while the program runs — that's the "dynamic" in dynamic data structure.

3.3 Types of Linked Lists

Table 3.1 — The four flavours
TypeEach node hasLast node points toUse case
Singly linkeddata + nextNULLSimple stacks/queues
Doubly linkeddata + next + prevNULL (prev of head also NULL)Browser history, undo, text editors
Circulardata + nextBack to HEADRound-robin scheduling, music playlists
Doubly circulardata + next + prevBoth directions loopMedia players, schedulers
IMPORTANT

In a doubly linked list you can walk backwards for free (O(1) prev), but every node pays one extra pointer's memory and every insert/delete must maintain two links instead of one. Nothing is free in data structures.

3.6 Applications

  • Dynamic memory management — the OS free list is a linked list of free blocks.
  • Implementing stacks & queues (Chapter 04) without fixed capacity.
  • Polynomial representation — each term is a node (coefficient, power, next).
  • Music playlists / image viewers — next/previous navigation.
  • Browser history — a doubly linked list of pages.
  • Hash table chaining — collisions queue up as little linked lists.
REMEMBER

Forgetting free() after deletion = a memory leak. And dereferencing a freed node = undefined behaviour. In vivas, always mention "allocate with malloc, release with free" — it signals you actually understand heap memory.

3.7 Chapter Keypoints

KEY POINT

Node = data + pointer. List = nodes chained by pointers.

KEY POINT

No random access: reaching the k-th node costs O(k).

KEY POINT

Insert/delete at a known position: O(1) — just rewire pointers.

KEY POINT

Circular list: last node's next = head. Doubly: every node remembers prev.
