5.1 What is a Tree?

Linear structures (arrays, lists, stacks, queues) force data into a line. Real information is usually hierarchical — folders inside folders, a company org chart, a family tree. Enter the tree.

DEFINITION

A tree is a non-linear data structure that represents hierarchical relationships. It consists of nodes connected by edges, with one special node called the root, and every other node reachable from it by exactly one path.

REMEMBER

Height vs depth: depth is measured down from the root (how deep is this node?), height is measured up from the leaves (how tall is this tree?). A tree with one node has height 0 when counting edges — check which convention your syllabus uses and state it in the exam.

5.2 Binary Trees

DEFINITION

A binary tree is a tree in which every node has at most two children — a left child and a right child (either or both may be absent).

The formulas examiners can't stop asking

FORMULA — LEVELS & NODES
Max nodes at level ℓ = 2ℓ   •   Max nodes with height h = 2h+1 − 1
height h counted in edges · a perfect tree of height h has all 2^(h+1)−1 slots filled
FORMULA — HEIGHT FROM NODES
Min height for n nodes = ⌈log₂(n + 1)⌉ − 1   •   Min leaves = 1   •   Max leaves = ⌈n / 2⌉
n nodes in a binary tree → height between ⌈log₂(n+1)⌉−1 (balanced) and n−1 (a chain)
EXAMPLE

Problem

What is the maximum number of nodes in a binary tree of height 3? And the minimum number of nodes for height 3?

Solution

Max = 23+1 − 1 = 2⁴ − 1 = 15 (the perfect tree).

Min = h + 1 = 4 (each level exactly one node — a skewed/ degenerate tree that's secretly a linked list).

5.3 Types of Binary Trees

FULL / STRICT

Every node has 0 or 2 children. Nobody has exactly one.

COMPLETE

All levels full except possibly the last, which fills left to right. This is what heaps use.

PERFECT

All levels completely full. Exactly 2^(h+1) − 1 nodes. The symmetric fairy-tale tree.

SKEWED / DEGENERATE

Every node has one child — the tree collapses into a chain (effectively a linked list; operations degrade to O(n)).

BALANCED

For every node, left and right subtree heights differ by at most 1 (AVL trees enforce this to keep O(log n) search).

BINARY SEARCH TREE

Ordered tree: left < node < right at every node. Search/insert/delete in O(h).

IMPORTANT

Inorder traversal of a BST gives sorted output. That's not a coincidence — it's the definition of the BST ordering flowing through the traversal. Guaranteed 2-mark question.

REMEMBER

To hand-trace any traversal: draw a small path that hugs the tree counter-clockwise and write each node when you touch it from the correct side — left side for inorder, top for preorder, bottom/right for postorder. Practise on Fig 5.1 until the outputs come out in your sleep.

5.5 Binary Search Tree (BST)

DEFINITION

A binary search tree is a binary tree where, for every node: all keys in the left subtree are smaller, all keys in the right subtree are greater.

That one rule turns searching into a guided missile: at each node, compare and discard half the tree.

  • Search / insert / delete: O(h) — O(log n) if balanced, O(n) if skewed.
  • Insertion of already-sorted data produces a skewed tree — the reason AVL/red-black trees exist.
  • Inorder traversal = sorted list.

5.6 Applications of Trees

  • File systems — directories and files form a tree.
  • Expression trees — compilers build them from your arithmetic; inorder/postorder traversals reproduce the expression forms.
  • Heaps — complete binary trees powering priority queues.
  • Huffman coding — compression via a binary tree of frequencies.
  • Databases / indexes — B and B+ trees.
  • HTML DOM — the web page you're reading is a tree. It's trees all the way down.
