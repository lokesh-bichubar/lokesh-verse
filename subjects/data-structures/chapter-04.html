STACKS & QUEUES

QUANTUM UNIVERSITY B.TECH CSE SEMESTER 01
FULL NOTES ONE-SHOT REVISION

4.1 The Stack — LIFO

A stack is exactly what it sounds like: a pile of plates. You put a plate on top, and you take a plate from the top. The last plate in is the first plate out.

DEFINITION

A stack is a linear data structure that follows LIFO — Last In, First Out: insertion and deletion happen only at one end, called the top.

Core operations

Table 4.1 — Stack operations (all O(1))
OperationDoes whatError condition
push(x)Put x on topOverflow — stack is full
pop()Remove & return topUnderflow — stack is empty
peek() / top()Read top without removingUnderflow
isEmpty()Is there anything there?—
isFull()Array-based only—
REMEMBER

Overflow = pushing into a FULL stack. Underflow = popping an EMPTY stack. Exams swap these on purpose. Also: top = -1 means empty; top == SIZE-1 means full — for an array stack indexed from 0.

4.2 Applications of Stacks

  • Function calls & recursion — the call stack holds return addresses and locals. Deep recursion = stack overflow, the runtime error named after this very structure.
  • Expression conversion & evaluation — infix → postfix, then evaluating postfix (see below).
  • Undo / Redo — every action pushes onto an undo stack.
  • Browser back button — URLs pushed as you browse.
  • Matching brackets / parentheses — push opening, pop on closing, fail on mismatch.
  • Backtracking — mazes, DFS: push choices, pop when stuck.

Infix → Postfix (the classic exam question)

EXAMPLE

Problem

Convert A + B * C and (A + B) * C to postfix.

Solution

A + B * C → A B C * +  (* has higher precedence, so B*C happens first)

(A + B) * C → A B + C *  (brackets force + first)

Rule of thumb: in postfix, operators appear after their operands, and precedence/brackets are baked into the order — so no brackets survive and no precedence rules are needed at evaluation time.

4.3 The Queue — FIFO

DEFINITION

A queue is a linear data structure that follows FIFO — First In, First Out: insertion happens at the rear, deletion happens at the front.

The problem with the simple array queue

After a few dequeues, the front of the array becomes unusable "dead space" — even though the queue is nearly empty, the rear pointer hits the end. This is the false overflow problem, and the fix is elegance itself:

IMPORTANT

The circular queue treats the array as a ring: when a pointer runs off the end, it wraps back to index 0 using modulo arithmetic. No space is ever wasted.

FORMULA
rear = (rear + 1) mod n   •   front = (front + 1) mod n
n = capacity of the array · wrap-around in one line of arithmetic

4.4 Types of Queues

SIMPLE QUEUE

Plain FIFO. Suffers false overflow once the front fills with dead space.

CIRCULAR QUEUE

Ring layout with mod wrap-around. The fix for false overflow.

DEQUE

Double-ended — insert and delete at both ends. A stack and a queue at the same time.

PRIORITY QUEUE

Elements with higher priority come out first, regardless of arrival time. OS schedulers and Dijkstra live here.

4.5 Applications of Queues

  • CPU scheduling — ready queue of processes (round-robin uses a circular queue).
  • Printer spooling — jobs print in arrival order.
  • BFS graph traversal — explores level by level (Chapter 06).
  • Keyboard buffer / IO buffers — keystrokes queue up.
  • Call center systems — "your call is important to us" is a queue speaking.
